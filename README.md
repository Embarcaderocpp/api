# Bank Lab — напиши свой банковский backend

Это учебный каркас на Java 21, Spring Boot 3.5.16 и Maven.
Ты самостоятельно реализуешь банковскую часть: от схемы PostgreSQL до защищённых переводов.
В проекте нет готового решения, спрятанных ответов или имитации банка в памяти.

## Что работает сейчас

- Spring Boot запускается без БД и Docker.
- `GET /api/v1/system/status` возвращает технический статус приложения.
- Есть один тест запуска контекста и этого endpoint.
- Maven Wrapper фиксирует версию Maven 3.9.11.

**Банковские endpoints пока не существуют.** Зелёная сборка проверяет только каркас.
JPA, PostgreSQL, Flyway, Security и Testcontainers нужно подключить самостоятельно
на соответствующих этапах. Это тоже часть обучения.

## Быстрый запуск в Windows

Нужен JDK 21. Открой `pom.xml` как Maven-проект в IntelliJ IDEA,
выставь Project SDK, Maven Importer JDK и Maven Runner JRE на 21.
В настройках Maven выбери Wrapper.

В PowerShell из корня проекта:

```powershell
java -version
.\mvnw.cmd verify
.\mvnw.cmd spring-boot:run
```

В другом терминале:

```powershell
Invoke-RestMethod http://localhost:8080/api/v1/system/status
```

Ожидаемый JSON:

```json
{"application":"bank-lab","status":"UP"}
```

Остановка приложения — `Ctrl+C`. В Linux/macOS используй `sh ./mvnw` вместо `.\mvnw.cmd`.
При первом запуске Wrapper скачивает Maven и зависимости: нужен доступ к Maven Central.

Если `java -version` показывает другую Java или зависает, задай `JAVA_HOME`
на папку своего JDK 21 и добавь его `bin` в начало `PATH`. Пример для текущего компьютера:

```powershell
$env:JAVA_HOME = 'C:\Users\pc\.jdks\openjdk-21.0.2'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
.\mvnw.cmd verify
```

Эти команды меняют окружение только текущего терминала. Глобальные настройки менять не нужно.
Для запуска из IDE можно использовать `BankLabApplication`.

## Как проходить проект

1. Прочитай [требования к банку](docs/REQUIREMENTS.md).
2. Выполняй задания по [дорожной карте](docs/ROADMAP.md), отмечая критерии готовности.
3. На первом этапе заполни [рабочую тетрадь по БД](docs/DATABASE.md).
4. Контроллеры реализуй по [целевому контракту API](docs/API.md).
5. Пиши проверки из [плана тестирования](docs/TESTING.md).
6. Записывай свои решения в [журнал архитектуры](docs/DECISIONS.md).

**Первое задание:** запусти каркас, затем нарисуй собственную ER-диаграмму
для клиентов, учётных записей и счетов. Объясни связи и ограничения.
Только после этого переходи к SQL и JPA. Не нужно проектировать весь банк за один вечер.

## Что предстоит написать тебе

| Область | Твоя работа |
| --- | --- |
| База данных | ER-диаграмма, таблицы, типы, ключи, ограничения, индексы, SQL-миграции |
| Инфраструктура | PostgreSQL, Compose по желанию, окружение, позднее Dockerfile и CI |
| Модель | Сущности, DTO, отображение между ними, статусы |
| Доступ к данным | Репозитории, запросы, пагинация, блокировки |
| Бизнес-логика | Сервисы клиентов, счетов, переводов, выписок |
| HTTP | Банковские контроллеры, валидация, ошибки |
| Безопасность | Spring Security, пароли, аутентификация, права и владение ресурсами |
| Надёжность | Транзакции, конкуренция, идемпотентность, учёт денег |
| Проверки | Unit-, HTTP- и интеграционные тесты, Testcontainers |

Пакеты `auth`, `customer`, `account`, `transfer`, `ledger`, `shared`
содержат только `package-info.java` с заданиями. Сигнатуры сервисов и репозиториев
ты тоже проектируешь сам. Можно менять структуру, если можешь объяснить решение.

## Режим обучения

Делай небольшой законченный этап, тестируй его и сохраняй отдельным коммитом.
За помощью можно обращаться так: «проверь мою схему», «дай подсказку без решения»,
«объясни ошибку» или «проведи ревью сервиса». Готовый код всего этапа не нужен,
пока ты сам не решишь его запросить.

Уровень 1: этапы 0–4 — работающий банк с корректными переводами.
Уровень 2: этапы 5–7 — надёжность, учёт, тесты и оформление для резюме.
Не добавляй Kafka и микросервисы до завершения основной части.
