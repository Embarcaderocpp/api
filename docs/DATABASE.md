## Миграции и конфигурация

- [ ] Зависимости БД добавлены в `pom.xml`, их назначение понятно.
- [ ] Настройки datasource используют переменные окружения.
- [ ] Используется Flyway, а Hibernate проверяет соответствие сущностей схеме (`validate`).
- [ ] Миграции лежат в `src/main/resources/db/migration`.
- [ ] Подъём чистой базы и повторный старт приложения проверены.
- [ ] Новая миграция проверена на БД с данными предыдущего этапа.
- [ ] Пароли и локальные данные не попали в Git.

Помни: Spring Boot сам по себе не читает `.env` как настройки приложения.
Если используешь такой файл для Compose, продумай отдельно передачу переменных
в Java-процесс: через IDE, окружение терминала или конфигурацию контейнера.

## Проверки непосредственно через SQL

Сам напиши запросы для проверки следующих случаев:

- Дублирующий email и номер счёта отклоняются ограничениями БД.
- Нельзя сохранить связь с несуществующим владельцем.
- Недопустимая сумма не проходит выбранные ограничения.
- Для внутреннего перевода сумма движений равна нулю.
- Остаток каждого клиентского счёта совпадает с журналом, включая финансирование.
- Поиск истории использует подходящий индекс на достаточно большом наборе данных.

Сохрани свои диагностические SQL-запросы в отдельном каталоге, например `sql/`.
Не запускай изменяющие данные эксперименты на единственной копии своей dev-БД.
