# Целевой HTTP-контракт

Это задание, а не описание реализованного API. Сейчас работает только `GET /api/v1/system/status`.
Пути ниже заданы для согласованности; внутренние классы, DTO и схему БД проектируешь ты.
Идентификаторы в примерах условные — замени на реальные значения своего API.

## Общие правила

- Префикс `/api/v1`, JSON, суммы в JSON-строках: `"1500.00"`.
- RUB, до двух знаков после запятой. Неподдерживаемую валюту отклоняй.
- Время — ISO 8601 с часовым поясом, например UTC с суффиксом `Z`.
- На этапе 2 используй HTTP Basic. Отдельный `/login` в обязательный контракт не входит.
- Владельца определяй через Security, а не параметром `ownerId` от клиента.
- `401` — нет действительной аутентификации; `403` — запрещённая административная операция.
- Для чтения/изменения чужого ресурса возвращай `404`, как для отсутствующего.
- Все ответы об ошибках, в том числе от Security, должны иметь единый безопасный формат.

## Маршруты

| Метод и путь | Назначение | Успех |
| --- | --- | --- |
| `GET /system/status` | Публичная техническая проверка | `200` |
| `POST /auth/register` | Публичная регистрация | `201` |
| `GET /me` | Свой профиль | `200` |
| `POST /accounts` | Открыть свой счёт | `201` |
| `GET /accounts` | Список своих счетов | `200` |
| `GET /accounts/{id}` | Свой счёт и баланс | `200` |
| `POST /accounts/{id}/close` | Закрыть свой пустой активный счёт | `204` |
| `POST /admin/accounts/{id}/block` | Заблокировать активный счёт | `204` |
| `POST /admin/accounts/{id}/unblock` | Разблокировать счёт | `204` |
| `POST /transfers` | Перевести деньги | `201` |
| `GET /transfers/{id}` | Доступный клиенту перевод | `200` |
| `GET /accounts/{id}/transactions` | Выписка своего счёта | `200` |

Во всех строках таблицы подразумевается префикс `/api/v1`.
Недопустимый переход статуса счёта — `409`, неизвестный счёт — `404`.
Успешный `POST`, создающий ресурс, возвращает его идентификатор.

## Регистрация

```json
{
  "email": "alice@example.test",
  "password": "choose-your-local-test-password",
  "fullName": "Алиса Тестовая"
}
```

Успех возвращает `id`, `email`, `fullName`. Пароль и его хеш никогда не возвращаются.
Роль в публичном запросе не поддерживается. Повторный email — `409`.
Ограничения длины имени, email и пароля сформулируй и проверь сам.

## Открытие счёта

Тело запроса:

```json
{"currency":"RUB"}
```

Ответ включает `id`, `number`, `currency`, `balance`, `status`, `createdAt`.
Новый баланс `"0.00"`, статус `ACTIVE`.

## Перевод

```http
POST /api/v1/transfers
Content-Type: application/json
Idempotency-Key: demo-transfer-001
```

```json
{
  "fromAccountId": "replace-with-your-source-id",
  "toAccountId": "replace-with-your-destination-id",
  "amount": "300.00",
  "currency": "RUB"
}
```

Успешный ответ включает `id`, оба идентификатора счетов, `amount`, `currency`,
`status: "COMPLETED"`, `createdAt`. Повтор уже завершённого запроса с тем же ключом
и параметрами возвращает тот же `201` и то же тело ответа.

На этапе 4 можно реализовать перевод без ключа. С этапа 5 заголовок обязателен.
Ограничение длины ключа выбери и документируй.

| Ситуация | HTTP | Код ошибки |
| --- | --- | --- |
| Неверное тело, сумма ≤ 0, лишние дробные знаки, превышение лимита, нет ключа | `400` | `VALIDATION_ERROR` |
| Неподдерживаемая валюта | `400` | `UNSUPPORTED_CURRENCY` |
| Отсутствующий или чужой счёт списания, отсутствующий получатель | `404` | `ACCOUNT_NOT_FOUND` |
| Один и тот же счёт с обеих сторон | `400` | `SAME_ACCOUNT` |
| Недостаточно средств | `409` | `INSUFFICIENT_FUNDS` |
| Любой из счетов не активен | `409` | `ACCOUNT_NOT_ACTIVE` |
| Тот же ключ, другие параметры | `409` | `IDEMPOTENCY_CONFLICT` |

Порядок проверок должен исключать раскрытие баланса и статуса чужого счёта списания.
Поведение при ещё выполняющемся запросе и временных конфликтах БД опиши сам.

## Формат ошибки

```json
{
  "code": "INSUFFICIENT_FUNDS",
  "message": "Недостаточно средств",
  "path": "/api/v1/transfers",
  "timestamp": "2026-01-01T12:00:00Z"
}
```

Можно добавить список ошибок отдельных полей. Не отдавай stacktrace, SQL,
пароли или внутренние детали БД. `code` предназначен для программной обработки.

## Выписка

```http
GET /api/v1/accounts/{id}/transactions?page=0&size=20&from=2026-01-01T00:00:00Z&to=2026-02-01T00:00:00Z
```

`from` включительно, `to` исключительно; фильтры необязательны.
`page` начинается с 0, `size` по умолчанию 20, допустим 1–100.
Неверный диапазон или пагинация — `400`.
Сортировка: сначала самые новые; при равном времени используй стабильный второй ключ.
Ответ: `items`, `page`, `size`, `totalElements`.
Элемент: идентификатор движения, ссылка на операцию, сумма со знаком,
валюта и время. Формат ссылки для начального финансирования опиши сам.

Для списка счетов используй такую же оболочку пагинации и ограничение размера.
Пагинацию, фильтрацию и сортировку выполняй в БД, не загружая всю историю в Java.
